# 阿禾的故事与剧情视频接入

## 故事定位

**一个失去父母、与奶奶相依为命的姑娘，靠手艺与经营逐步拿回生活的决定权。**

用户已经确定的设定：父母在阿禾幼年车祸离世；奶奶抚养她长大；叔叔婶婶侵占遗产并持续欺压；她无权无势、热爱手作，靠自己站稳脚跟；前期与中后期都有欺负和压迫。

叙事建议：外部冲突可以尖锐，店内仍然保留彩铅画风的温度。让玩家在祖孙陪伴、客人的心意和亲手完成的作品里获得喘息。朋友提供见证、信息和合作，关键作品与经营决定仍由阿禾完成。车祸保持为既定身世，不额外添加谋杀阴谋。

## 本次已接入原型

保留现有三消和串珠手感，增加三章主线、7 段主线剧情、3 段装修支线、6 件可阅读的记录与回忆、首页阶段目标和视频播放入口。现有六份订单是一个浓缩的成长篇，不等于完整长线故事。

|阶段|外部冲突|玩家实际操作|交付后的故事变化|
|---|---|---|---|
|序章|叔婶推诿遗产账目，嘲笑阿禾开店|阅读身世，接第一份委托|明确“先靠手艺生活”的目标|
|雏菊订单|婶婶要求交出店铺收入|三消收珠、搭配手串、交付|第一笔收入入账；读完剧情收好收据|
|海风订单|抄袭与流言出现，婶婶继续贬低|完成第二份定制|小满带来原始沟通记录；收好草图|
|许老师订单|叔叔要求关店|完成定制，阅读并收好确认记录|许老师见证真实创作过程|
|小森林订单|流言、低价竞争后又出现苛刻合作|用老客订单稳住经营|采购方要求买断署名，叔叔企图代管；阿禾暂不签约|
|紫雾参展订单|资源方和亲属试图控制她|制作署名参展作品|独立参展；开始整理遗产咨询材料|
|给自己的手串|遗产争议仍未解决|完成奶奶的委托|承认取得的成长，准备正式求助，留下后续故事入口|

当前主线中的拒签、求助等决定是写好的剧情，不是已经实现的分支选择系统。当前没有法庭玩法、供应链玩法或可操作的遗产诉讼系统。

### 玩法之间的关系

`当前困境 → 顾客委托 → 三消获得实际库存 → 亲手串珠 → 交付获得收入与口碑 → 剧情后果 → 装修和生活支线 → 下一份委托`

- **三消**提供当前订单需要的真实珠材。采珠入口显示当前任务，避免与剧情脱节。
- **串珠**是阿禾解决问题的能力：作品记录、手艺和对客人心意的理解会带来口碑与伙伴。
- **订单**同时承载个人愿望与主线进展；不是每个客人都带来新的坏消息。
- **装修**由玩家决定先后，不强迫买指定家具才能继续订单。升级奶奶的椅子解锁温暖回忆；升级工作桌解锁母亲的珠盒；升级展示柜解锁作品署名支线。当前均为剧情收益，不额外发放生产加成。
- **手账**区分已读、未读和未解锁剧情。读完对应片段后收好收据、草图、顾客记录、合同草案、参展卡和旧珠盒；点击物件可看说明和重温。

父母的珠盒是情感遗物，不能突然变成能证明一切的证据。独立收入也不能自动解决遗产权属。遗产线需要后续核查资料、寻求专业帮助和面对对方回应。

## 长线扩充建议：八章结构

以下是后续制作建议，尚未作为完整关卡加入游戏。正式扩充时，应把每章拆成若干有因果关系的订单与任务，不把八章故事压缩进六张订单。

|章节|冲突升级|与玩法相连的主动目标|阶段性回报|
|---|---|---|---|
|1 旧桌上的第一束光|叔婶侵占遗产、挤压祖孙生活|做成第一单，整理自己的收支|第一笔自主收入，祖孙有一个能开工的角落|
|2 属于我们的门牌|羞辱和“替你保管收入”的控制|做出回头客订单，添置基础工作台|稳定开门，形成自己的客人名单|
|3 被抹掉的名字|邻店抄袭，亲属附和造谣|留存草图、试串和沟通记录，做出代表作|第一次公开署名，有人愿意见证|
|4 断掉的珠线|供应商受压、供货条件变差|寻找替代材料，设计新配色并兑现交期|获得第二条可靠供货渠道|
|5 机会的价码|展位与独家、买断署名捆绑|核对条款，筹备独立参展作品|保留名字与经营选择，有合理代价也有新机会|
|6 她们想把店拿走|叔婶趁经营扩大索要控制权，旧流言再次传播|整理独立经营资料，与真实顾客沟通|建立边界，开始正式咨询遗产问题|
|7 把账翻开|对方拒绝提供完整资料、拖延回应|核查来源、列出缺失材料、获得合适的专业协助|遗产争议出现可信的程序进展，不靠一次三消定胜负|
|8 由我决定的明天|品牌、团队和持续经营的新压力|完成原创系列，搭建更成熟的小店|阶段性守住经营与生活，保留下一季空间|

压迫要改变阿禾面临的选择，并随着她成长而改变形式。避免反复让同一角色进门辱骂，再靠下一单金币解决。每次重要冲突后至少给一个主动目标、一个可见成果和一小段日常陪伴。不要为了制造戏剧性扣走已经挣到的金币、摧毁已购家具或强迫玩家付费脱困。

### 开场约 10–15 分钟的制作节拍建议

时长是设计目标，尚未经过玩家时长验证。

1. 约 30–45 秒：序章视频或对白，交代父母离世、祖孙处境和叔婶的控制，结尾落在阿禾伸手打开旧珠盒。
2. 第一单：林阿姨提出给母亲的礼物需求。玩家立即获得一个具体、可以完成的目标。
3. 三消：完成一次采珠。失败可重试，不追加羞辱剧情，不扣走已有库存。
4. 手作：亲手串满 12 颗，搭配雏菊吊坠，包装交付。
5. 约 15–25 秒：顾客感谢与婶婶索款形成转折，阿禾坚持自己记账。玩家在片段结尾收好第一张订单收据。
6. 自由选择：用收益先换奶奶的椅子、升级工作桌或留着钱。装修支线提供情感回报。
7. 下一单：小满登场，先建立朋友关系，再逐步引出抄袭冲突。

## 视频应该插在哪里

优先制作“改变目标或关系”的片段：开场身世、第一次维护收入、抄袭被揭开、苛刻合同、独立署名、本篇结尾。普通接单、缺珠、装修操作使用界面和短对白，避免玩家每操作一次就被打断。

所有视频都作为对应场景的**完整文字剧情的替代呈现**。视频播完显示本段小结，玩家点击收好这一页；跳过视频会进入完整文字版。不要依赖视频里某一帧去发钱、扣库存或改变关卡状态。

|剧情 ID|触发条件|推荐片段|建议长度|
|---|---|---|---|
|`old-table`|首次进入；手账可重温|童年身世 → 叔婶压迫 → 打开珠盒|30–45 秒|
|`first-receipt`|交付雏菊订单|顾客感谢 → 索要收入 → 收据留下|15–25 秒|
|`stolen-design`|交付海风订单|小满告知抄袭 → 阿禾决定留存原稿|20–30 秒|
|`design-record`|交付许老师订单|见证创作 → 叔叔要求关店 → 拒绝|20–30 秒|
|`unfair-contract`|交付小森林订单|合同压价买断 → 暂不签约|25–40 秒|
|`own-name`|交付紫雾订单|独立展签 → 婶婶再施压 → 整理咨询材料|25–35 秒|
|`first-independence`|交付奶奶订单|给自己的手串 → 祖孙相伴 → 下篇预告|25–40 秒|
|`grandma-chair`|椅子首次升级后可在家具卡或手账打开|祖孙生活片段|10–20 秒|
|`keepsake-box`|工作桌首次升级后可打开|整理母亲的旧珠盒|15–25 秒|
|`signed-display`|展示柜首次升级后可打开|作品署名与新陈列|10–20 秒|

最值得先做的是 `old-table`、`unfair-contract` 和 `first-independence`，其余片段已有对白可用。不要为了覆盖所有片段而降低画面一致性。

### 制作规格建议

- 竖屏 9:16，建议保留 1080×1920 母版，网页交付优先 720×1280。
- MP4，H.264 视频、AAC 音频、24 或 30 fps；编码采用常见的 yuv420p，并把 moov 索引前置以便网页播放。具体压缩以手机实测为准。
- 单段尽量 15–40 秒，开场可稍长；短片段优先控制在约 3–8 MB，避免把整章做成一个大文件。
- 同时交付 JPG 海报、带时间码的中文字幕 `.vtt` 和完整台词文本。代码里的文字版也应与最终视频同步。
- 人物造型、旧珠盒、奶奶的椅子、店面和配色保持一致。奶奶和阿禾的手部特写适合承接“视频结束 → 玩家开始串珠”。
- 关键人物表情和手串放在画面中间区域，字幕不要贴底；网页还会显示播放器控制条。
- 当前叔婶、顾客和采购方尚无独立角色立绘，文字版以姓名卡显示，避免用阿禾的头像冒充这些人物。后续角色视频应先统一人物设定。

## 把你制作好的视频放进游戏

例如先替换序章：

1. 将文件放进项目：

   ```text
   public/videos/old-table.mp4
   public/videos/old-table.jpg
   public/videos/old-table.zh.vtt
   ```

2. 打开 `public/story-media.json`，把 `old-table` 的条目改为：

   ```json
   "old-table": {
     "src": "videos/old-table.mp4",
     "poster": "videos/old-table.jpg",
     "captions": "videos/old-table.zh.vtt"
   }
   ```

   其他条目保持原样。路径从 `videos/` 开始，不加 `/` 或 `public/`，这样部署到 GitHub Pages 的仓库子路径后仍能加载。海报和字幕没有准备好时可以留空；正式交付建议补齐。

3. VTT 文件示例（UTF-8 编码）：

   ```text
   WEBVTT

   00:00:00.000 --> 00:00:04.000
   阿禾幼年时，父母在一场车祸中离世。

   00:00:04.000 --> 00:00:08.000
   此后，是奶奶陪她长大。
   ```

4. 本地打开手账重温对应片段。确认字幕、声音、竖屏画面和结束后的收好按钮，再执行测试与生产构建，推送更新。

   ```sh
   npm test
   npm run test:story
   npm run build
   ```

替换已有视频时建议更换文件名，例如 `old-table-v2.mp4` 并更新配置，避免浏览器继续使用旧缓存。现在所有 `src` 均为空，游戏没有虚构或请求尚未制作的视频。

### 已实现的播放与存档规则

- 用户点击播放，不依赖手机浏览器允许有声自动播放；使用 `playsinline` 支持页内播放。
- 游戏声音关闭时视频默认静音；原生视频控制条保留暂停、进度和音量等浏览器支持的控制。
- 可以随时关闭，稍后从手账重温；中途关闭不会标记为已读。当前不会记忆视频播放到第几秒。
- 文件损坏或格式不支持时回退完整文字；播放被浏览器拒绝时提供重试或文字入口。网络缓冲时也始终保留文字入口。
- 播放结束进入小结，再由玩家确认完成这一段；关闭视频、切换文字或退到后台都会暂停视频。
- 视频只在打开该片段时读取元数据，不在游戏启动时下载全部影片。配置文件无法加载时使用文字剧情。
- 剧情用稳定 ID 保存已读状态。奖励仍由真实订单交付结算；重温和跳过视频都不重复发奖励。
- 旧存档的珠材、金币、装修、订单和图鉴保留。改写后的故事作为未读内容开放，玩家可以在手账补看。

## 验证边界

自动化验证覆盖真实浏览器视频播放结束、切换文字、重温、媒体损坏回退、播放被拒绝、旧存档保留及手机/桌面布局。测试片段临时在内存生成，不作为正式剧情素材发布。

未来实际 MP4、配音、字幕同步和 iOS/Android 真机仍需在拿到成片后逐段验收。
